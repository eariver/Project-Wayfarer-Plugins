# Wayfarer Core V0.0.1 Release Plan

## Outcome

Deliver `Wayfarer_Core-V0.0.1.jar` as a source-traceable, tested GitHub Release asset ready
for Project Wayfarer handoff. This plan does not authorize Project Runtime deployment.

## Scope

- Runtime artifact: `Wayfarer_Core` only.
- Supporting implementation: `wayfarer-api`, `wayfarer-common`, `wayfarer-testkit`,
  `wayfarer-core`.
- Build-only skeletons: Main, Frontier, LeafGrapple adapter.
- Excluded: Main and Frontier release artifacts and every EliteMobs–MVI adapter artifact.

## Gated sequence

| Gate | Slice | Exit condition |
|---|---|---|
| Preparation PR | Requirements, workflow, plans, evidence skeleton | `check`, `assemble`, review, merge |
| `V0.0.1-alpha.1` | Lifecycle Foundation | automated tests plus isolated lifecycle verification |
| `V0.0.1-alpha.2` | Persistence and Identity | migration, outage, identity, audit, restart evidence |
| `V0.0.1-alpha.3` | Redis and Task Boundary | reconnect, backpressure, shutdown, no-main-thread-I/O evidence |
| `V0.0.1-alpha.4` | Waymark Transactions | idempotency, refund, UNKNOWN, reconcile, restart evidence |
| `V0.0.1-beta.1` | Feature Complete | full automated and packaging/API checks; docs complete |
| `V0.0.1-rc.1` | Release Candidate | full isolated test-server report and handoff package |
| `V0.0.1` | Stable | approved RC source, traceability clear, explicit owner clearance |

Every failed candidate receives a new tag. Tags and assets are immutable.

## Verification per change

Run the narrowest module tests first, followed by:

```powershell
.\gradlew.bat --no-daemon check
.\gradlew.bat --no-daemon assemble
```

Before beta/RC, also verify configuration cache, reproducible packaging, API class identity,
forbidden assets, secrets, binaries, runtime data, migrations, and dependency direction.

## Approval

Before `prerelease.yml`, display repository, selected ref, source commit, release version,
scope, test instruction path, expected assets, and environment; wait for explicit approval.
Before `release.yml`, additionally display the approved pre-release, evidence and requirement
references, traceability, limitations, decisions, and the user-provided
`requirements_cleared` value.

## Rollback and stop conditions

Source rollback uses a new corrective commit and candidate. Existing tags/assets are not moved
or overwritten. Runtime rollback is Project-owned and is documented in the handoff package.
Stop on any authority conflict, destructive migration, unsafe provider threading, forbidden data
access, main-thread blocking I/O, duplicate economy effect, or request for Project Runtime change.
