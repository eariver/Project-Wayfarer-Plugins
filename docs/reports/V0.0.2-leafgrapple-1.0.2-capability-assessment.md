## Observed public boundary

- `LeafGrapplePlugin.hookItemService()`;
- `HookItemService.getTiers()`;
- `HookItemService.createHookItem(HookTier)`;
- `HookTier.durabilityEnabled()`;
- `HookTier.entityHookSettings()`;
- `EntityHookSettings.enabled()`.

The version adapter isolates these class names behind reflection. No LeafGrapple class enters the
Frontier domain or a public Wayfarer API.

## Fail-closed result

The examined default configuration has a single `wood` tier with:

- durability enabled; and
- entity hooking enabled (players disabled, other living entities enabled).

That tier does not satisfy the V0.0.2 requirements for a durability-free traversal hook with
entity/player hooking disabled. Setting Bukkit `ItemMeta.unbreakable` is insufficient because
LeafGrapple's own public behavior checks the tier and applies custom damage.

The adapter therefore exposes `UNSAFE_CONFIGURATION` unless a 1.0.2 tier reports both
`durabilityEnabled=false` and `entityHookSettings.enabled=false`. It does not create a fallback
hook, reimplement projectile/pull physics, or reach into private fields.

## Gate

The embedded public `config.yml` confirms a safe tier can be expressed without changing the JAR:

```yaml
hooks:
  wayfarer:
    durability:
      enabled: false
    entity-hook:
      enabled: false
      target:
        players: false
        mobs: false
        animals: false
        monsters: false
```

The remaining movement/range/display values must be copied from a reviewed tier rather than
guessed. The Plugin adapter/fail-closed source boundary is accepted for `FRONT-D02`; a temporary
test-only safe tier and bounded client-motion gate remain. The temporary values are not a
production balance recommendation. No LeafGrapple fork, private reflection, or Wayfarer fallback
physics is required. This repository does not modify the external artifact or Project runtime
configuration.
