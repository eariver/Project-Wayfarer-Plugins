## Semantics

Explicit fixed-source Vault success/failure is mapped without exposing raw messages. Provider
exceptions, timeout/null results, and uncertain post-dispatch failures remain ambiguous and become
engine `UNKNOWN`. Core retains its unique idempotency key, durable per-effect operation identity,
single winning provider call, normal duplicate debit/refund prevention, manual reconcile, and
audit behavior. It does not claim exactly-once.

## Accepted limitation and future action

Vault success precedes durable Redis completion. There is no atomic operation ID, effect lookup,
or crash-window resolution. This is shared by all current Vault economy consumers, not unique to
Wayfarer.

If stronger guarantees are later required, replace or improve Vault, RedisEconomy, or both through
a boundary every economy consumer can share. Do not add a Wayfarer-only RedisEconomy side channel.
The Project owner should transfer this item to a Project deferred-design record such as
`docs/11-deferred-design-items.md`.
