# V0.0.1-alpha.3 Test Plan — Redis and Task Boundary

- Release scope: `core`
- Requirement IDs: DATA-002, THREAD-001, THREAD-002, CORE-006, TEST-003
- Test environment: Java 25; isolated Redis and MariaDB; Paper 1.21.11
- Redis image authority: `redis:8-alpine`, from `eariver/Project_Wayfarer` commit
  `344eedc738d75954daa43facfeef302944f2963a`, compose blob
  `42e62979c8c70290fae78c0731ae628e940d74e9`; password auth and AOF enabled
- Automated tasks: `test`, `mariaDbIntegrationTest`, and `redisIntegrationTest`; all included by
  `check`

## Automated

- Verify Redis disabled/connected/outage/reconnect/clean-close health.
- Verify schema-versioned cache, bounded TTL, miss/outage authority fallback, owner-token lease,
  compare-and-delete, versioned Pub/Sub, self-message/duplicate/invalid rejection, and advisory
  idempotency hints.
- Exercise bounded queues, rejection/backpressure, timeouts, concurrency, and graceful shutdown.
- Disable during async work, drain accepted queued work, and prove new work and callbacks are
  rejected after closure.
- Verify immutable snapshot/result bridge, stale-result non-mutation, and Bukkit/mutable data
  rejection.
- Detect and fail main-thread Redis/JDBC I/O.
- Verify Redis outage degrades or rejects only documented operations.

## Runtime

Verify outage, reconnect, queue pressure, disable during operation, shutdown timeout audit, no
tick stall, and no main-thread network I/O.

## Exit

All failure behavior is explicit and restart-safe; no Redis-only persistent authority exists.
The local Docker Engine is intentionally not started; Redis/MariaDB execution is claimed only
from updated-head GitHub Actions.
