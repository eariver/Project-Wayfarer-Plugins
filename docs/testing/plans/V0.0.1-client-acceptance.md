## Preconditions

- The stacked PRs have been reviewed and merged in order, and the candidate identity is immutable.
- Testing occurs in an Owner-approved isolated runtime with backups and restore instructions.
- The sanitized configuration and environment references are reviewed; no secret is copied into
  evidence.
- The candidate reports enabled health before a player joins.
- Do not execute concrete Waymark debit/refund cases while ADR 0006 is blocked.

## Client-only checkpoints

| ID | Owner action | Expected result |
|---|---|---|
| CA-01 | Join as a real player, then disconnect and reconnect once | No freeze/disconnect; the same canonical UUID is retained and the last-known name snapshot is updated |
| CA-02 | Observe the approved DB evidence through the Project-owned procedure | One UUID-authoritative player row; no Player object or normal inventory data is stored |
| CA-03 | Run `/wayfarer admin health` without permission | Command is denied, no internal detail or secret is shown, and denial audit follows the approved policy |
| CA-04 | Run `/wayfarer admin health` with `wayfarer.admin.health` | Readable component status appears; with `player-details=false`, internal parenthetical details are suppressed |
| CA-05 | Exercise inspect/reconcile permission denial as a non-authorized player | No transaction mutation occurs and output remains sanitized |
| CA-06 | As an authorized player, issue reconcile without trailing `confirm` | Usage/confirmation is required and no action occurs |
| CA-07 | Move, chat, reconnect, and repeat the health command during the focused smoke | No visible server freeze, unexpected latency, kick, or duplicate command/service behavior |
| CA-08 | Item/PDC player workflow | Record `N/A — Core-only V0.0.1 has no player item issuance path`; do not add gameplay to create one |
| CA-09 | Waymark balance/debit/refund | Record `BLOCKED — ADR 0006` unless a separate Owner-approved concrete-provider authority decision exists |

## Stop conditions

Stop immediately on candidate/hash mismatch, migration validation failure, Core fail-closed,
unexpected permission grant, secret disclosure, duplicate identity/effect, persistent client
freeze, or an unapproved concrete-provider requirement. Do not relax config, migration, permission,
or release gates to continue.

## Rollback boundary

Stop the isolated server using its approved procedure, preserve evidence, and restore the isolated
backup. Do not edit or delete Flyway history, do not reverse V001–V003, and do not perform any
Project Runtime rollback from this repository. Record the incident before retrying.
