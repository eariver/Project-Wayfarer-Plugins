# V0.0.1-alpha.2 Test Plan — Persistence and Identity

- Release scope: `core`
- Requirement IDs: DATA-001, THREAD-001, CORE-004, CORE-005, TEST-002
- Test environment: Java 25; isolated MariaDB; Paper 1.21.11
- PR A Testcontainers image: `mariadb:11.8`, fixed by
  `eariver/Project_Wayfarer` `infrastructure/compose.yml` blob
  `42e62979c8c70290fae78c0731ae628e940d74e9`
- PR A automated task: `:plugins:wayfarer-core:mariaDbIntegrationTest`, included by `check`

PR A covers the internal pool/migration lifecycle, current V001 schema properties, failure
boundaries, and shutdown drain ordering only. Durable audit, player/item identity, repositories,
and the public database contract remain PR B or later work.

## PR A automated

- Migrate an empty database; validate an already migrated database; preserve applied migrations.
- Prove only `wf_core_*` is created by Core and validate the current V001 UUID column shape, UTC,
  JSON checks, indexes, and unique constraints.
- Inject DB outage and migration failure and verify fail-closed cleanup.
- Detect and fail any main-thread JDBC access.
- Stop new database intake independently of lifecycle callbacks, drain accepted and queued work
  before Hikari close, and distinguish drained, timed-out, and interrupted results.
- Commit two accepted operations against isolated MariaDB while disable waits, then verify both
  durable effects, health transitions, service unpublication, and graceful executor shutdown.

## PR B or later automated

- Implement and verify durable audit history behavior.
- Implement player/item identity validation.
- Implement repository optimistic-locking behavior.
- Implement repository restart recovery.

## Runtime

After PR A is reviewed and merged, verify empty migration, restart, DB outage, migration failure,
health transitions, cleanup, and no secret exposure on an isolated test server. Identity and
durable-audit runtime cases remain blocked on PR B. Paper runtime evidence for persistence drain
ordering remains pending. Do not run against Project databases.

## Exit

Automated and isolated results are commit-pinned; no applied migration was modified; schema and
known limitations are documented.
