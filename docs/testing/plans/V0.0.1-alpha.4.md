# V0.0.1-alpha.4 Test Plan — Waymark Transactions

- Release scope: `core`
- Requirement IDs: CORE-007, CORE-008, TEST-004
- Test environment: isolated MariaDB/Redis and supported Waymark provider boundary

## Preconditions

Record the provider version, supported API/Vault boundary, capability probe, and verified thread
contract. Stop for an owner decision if safe invocation cannot be established.

## Automated

- Cover every transaction state and allowed transition, provider reference, timeout, retry,
  insufficient funds, outage, crash windows, UNKNOWN, automatic/manual reconcile, and audit.
- Reuse an idempotency key and prove no duplicate debit or refund under concurrency/restart.
- Prove external-provider operations are not claimed as unconditional exactly-once.
- Verify inspect/reconcile permissions, confirmation, redaction, and console policy.

## Runtime

Verify balance, debit, refund, failure paths, duplicate requests, UNKNOWN/reconcile, restart
recovery, and provider outage using isolated accounts and explicit evidence.

## Exit

No duplicate economic effect or unresolved unsafe thread behavior exists.
