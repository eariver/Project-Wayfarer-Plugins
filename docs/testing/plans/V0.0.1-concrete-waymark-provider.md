## Validation completed before the gate

- Inspect the designated source commit and compatibility patch without modifying either.
- Inspect only the relevant fixed JAR classes and plugin descriptors.
- Establish service-registration timing, Vault method shape, cache/persistence order,
  failure propagation, operation-ID/lookup capability, and disable order.
- Confirm that the existing Core SPI/state machine can remain unchanged.

## Validation after an owner decision

If the proposed provider API is approved, add only the focused cases required by the request:

- discovery success/absence and safe provider ID;
- UUID balance mapping;
- debit success and insufficient funds;
- refund success;
- known pre-effect failure, post-dispatch ambiguity, timeout, and provider exception;
- no lookup capability only if that remains an approved mode; otherwise structured resolve;
- redaction and disable rejection;
- one representative transaction idempotency/refund/restart/reconcile path.

Then run focused tests, relevant MariaDB/Redis integration, `check`, `assemble`, one normal CI run,
and one dedicated Paper 1.21.11 build 132 / Java 25 standalone acceptance. Do not use Project
Runtime and do not repeat unrelated client, stress, crash-matrix, or identity tests.

No standalone runtime is authorized while ADR 0007 is unresolved because it would require an
unapproved provider implementation and could not establish the missing durability contract.
