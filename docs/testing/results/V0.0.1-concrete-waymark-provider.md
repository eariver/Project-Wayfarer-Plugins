## Known limitation

Vault `SUCCESS` proves only that the common Vault/RedisEconomy route accepted the operation. It
does not prove durable Redis completion, provider transaction-record completion, atomic operation
identity, effect lookup, or exactly-once. Concrete `resolve` therefore remains `UNKNOWN`; Core does
not infer an effect from balance and does not automatically repeat UNKNOWN debit/refund.

## Reproduction

Use the rc.3 candidate commit/JAR and fixed artifact hashes above in an isolated Paper 1.21.11 build 132
environment with task-only MariaDB 11.8/Redis 8. Enable `waymark.provider-mode: vault`, require
`expected-provider: RedisEconomy`, and run the production-excluded probe. Never use Project
DB/Redis, inspect RedisEconomy internal keys, or treat the PASS marker as durable Redis proof.
